# 饰品开发指南

本文介绍如何在 TerraMC 中注册一个新饰品、实现其具体效果，并为其配置可调数值。

## 1. 核心概念

TerraMC 采用一套自定义的「饰品抽象层」，将饰品拆分为三个相互独立的层次，便于扩展与维护：

| 概念 | 类 | 职责 |
| --- | --- | --- |
| 饰品物品 | `accessory.AccessoryItem` | 玩家能拿在手里/放进物品栏的实际物品，用 `accessoryId` 关联到饰品定义 |
| 饰品定义 | `accessory.AccessoryDefinition` | 把「饰品 ID + 物品 + 效果列表」绑定在一起 |
| 效果 | `accessory.AccessoryEffect` | 单一职责的行为单元，覆写钩子方法实现具体效果 |

此外还有两个支撑类：

- `accessory.AccessoryRegistry` —— 全局饰品注册表（存所有 `AccessoryDefinition`）。
- `accessory.AccessoryEvents` —— 事件分发器，把游戏事件转发给对应饰品的效果钩子。

> 说明：饰品槽位通过 **Curios API** 实现，与「汇流来世(Confluence)」使用同一套机制：
> `AccessoryItem` 实现 `ICurioItem`，只能放入「配饰(accessory)」栏位；
> 「是否装备」的判定在 `AccessoryManager.isEquipped()` 中通过 `CuriosApi.getCuriosInventory(...)` 完成。

## 3. 注册一个新饰品（完整步骤）

以「[群峦]原始直觉」为例，注册一个带两个效果的新饰品：

### 步骤 1：定义饰品 ID 与物品

在联动包（如 `compat/tfc/TfcAccessories.java`）中注册物品：

```java
public static final ResourceLocation PRIMAL_INTUITION = TerraMC.id("tfc_primal_intuition");

public static final DeferredItem<AccessoryItem> PRIMAL_INTUITION_ITEM = ModItems.ITEMS.register(
        "tfc_primal_intuition",
        () -> new AccessoryItem(PRIMAL_INTUITION, new Item.Properties().stacksTo(1)));
```

### 步骤 2：编写效果类

继承 `AccessoryEffect`，覆写需要的钩子，数值一律从配置读取：

```java
public class ThrownSpearDamageBonusEffect extends AccessoryEffect {
    public ThrownSpearDamageBonusEffect(String id) {
        super(id);
    }

    @Override
    public void onThrownProjectileHit(LivingIncomingDamageEvent event, ServerPlayer owner, Projectile projectile) {
        if (!TfcPrimalIntuitionConfig.enabled.get()) return;
        if (!ProjectileUtil.matchesType(projectile, TfcPrimalIntuitionConfig.spearProjectileTypes.get())) return;
        event.setAmount(event.getAmount() + TfcPrimalIntuitionConfig.thrownDamageBonus.get().floatValue());
    }
}
```

### 步骤 3：新增配置类

在 `config/` 下新建配置类，声明该饰品所有可调数值（见第 4 节）。

### 步骤 4：组装并注册饰品定义

```java
public static void register() {
    AccessoryRegistry.register(new AccessoryDefinition(
            PRIMAL_INTUITION,
            PRIMAL_INTUITION_ITEM,
            new ThrownSpearGlowEffect("glow"),
            new ThrownSpearDamageBonusEffect("thrown_damage_bonus")
    ));
}
```

并在 `TerraMC` 构造器中调用一次该 `register()`。

### 步骤 5：补全资源

- 模型：`assets/tm/models/item/tfc_primal_intuition.json`
- 纹理：`assets/tm/textures/item/tfc_primal_intuition.png`
- 语言：`assets/tm/lang/zh_cn.json` / `en_us.json` 中加入 `item.tm.tfc_primal_intuition`
- **Curios 槽位标签**：`data/curios/tags/item/accessory.json` 中加入 `tm:tfc_primal_intuition`
  （饰品必须加入 `curios:accessory` 标签，才能被放入「配饰」栏位）

## 4. 配置文件结构

配置文件生成于 `config/tm-common.toml`，结构如下：

```toml
[general]
    debugLog = false

[accessories.tfc_primal_intuition]
    enabled = true
    thrownDamageBonus = 4.0
    glowEnabled = true
    spearProjectileTypes = ["tfc:javelin"]
```

设计原则：

1. **一个饰品一个小节**：`[accessories.<饰品id>]`，字段由该饰品的配置类定义。
2. **每个数值都可配置**：效果代码中不硬编码数值，统一从配置读取。
3. **集中声明**：`TerraConfig` 静态块中按顺序调用各饰品配置类的 `init(builder)`。

### 新增一个饰品配置的模板

```java
public final class MyAccessoryConfig {
    public static final String ID = "my_accessory";

    public static ModConfigSpec.BooleanValue enabled;
    public static ModConfigSpec.DoubleValue someValue;

    static void init(ModConfigSpec.Builder builder) {
        builder.push(ID);
        enabled = builder.comment("是否启用").define("enabled", true);
        someValue = builder.comment("某个数值").defineInRange("someValue", 1.0, 0.0, 100.0);
        builder.pop();
    }
}
```

然后在 `TerraConfig` 的静态块里 `BUILDER.push("accessories")` 之后调用 `MyAccessoryConfig.init(BUILDER);`。

### 常用配置类型

| 需求 | API |
| --- | --- |
| 布尔开关 | `builder.define("key", true)` → `BooleanValue` |
| 整数 | `builder.defineInRange("key", 4, 0, 1000)` → `IntValue` |
| 小数 | `builder.defineInRange("key", 4.0, 0.0, 10000.0)` → `DoubleValue` |
| 字符串 | `builder.define("key", "value")` → `ConfigValue<String>` |
| 字符串列表 | `builder.defineList("key", List.of("a"), validator)` → `ConfigValue<List<? extends String>>` |

## 5. 如何实现一个具体效果

### 5.1 效果基类钩子

`AccessoryEffect` 提供以下可覆写钩子（默认空实现）：

- `onThrownProjectileHit(LivingIncomingDamageEvent, ServerPlayer, Projectile)` —— 投掷物命中时。
- `onProjectileSpawn(EntityJoinLevelEvent, ServerPlayer, Projectile)` —— 投掷物生成时。

### 5.2 新增事件钩子

若效果需要响应新的事件，在 `AccessoryEvents` 中新增 `@SubscribeEvent` 方法，找出事件的
「投掷物 + 主人」并遍历效果调用钩子；同时给 `AccessoryEffect` 增加对应钩子方法即可。

### 5.3 判定「矛类投掷物」的方式

示例通过「实体类型 ID 列表」判定（见 `ProjectileUtil.matchesType`），默认配置为 TFC 标枪实体
`tfc:javelin`，无需在编译期依赖群峦模组，也便于在配置中增删。

如果后续希望用更精确的类判定（`instanceof`），可将群峦加入 `compileOnly` 依赖后改写：

```java
if (!(projectile instanceof net.dries007.tfc.common.entities.ThrownJavelin)) return;
```

## 6. Curios 饰品槽位（与汇流来世一致）

TerraMC 的饰品通过 **Curios API** 接入，与汇流来世共用「配饰(accessory)」栏位：

1. **`AccessoryItem implements ICurioItem`**：覆写 `canEquip` / `canEquipFromUse`，
   仅在 `slotContext.identifier().equals("accessory")` 时返回 `true`，即只能放入配饰栏位。
2. **物品标签**：饰品需加入 `data/curios/tags/item/accessory.json`（`curios:accessory` 标签），
   与汇流来世自己的饰品标签合并，Curios GUI 才会允许放入。
3. **装备判定**：`AccessoryManager.isEquipped()` 调用
   `CuriosApi.getCuriosInventory(player)` → `handler.isEquipped(stack -> ...)` 查询当前装备。

新增饰品时只需完成「注册物品 + 加入标签」，其余效果与配置代码无需改动。
